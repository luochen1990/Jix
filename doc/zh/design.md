Jix 语言设计理念
==============

动机
---

- 解决 Nix 语言缺乏静态类型系统的问题 （无法提供与静态类型语言相似的 IDE 编辑体验）
- 改进复杂配置文件的可审查性和可维护性问题
- 改进对非 Nix 用户友好性的问题 (通过兼容 JSON 语法)

原则
---

- 对非 Nix 用户友好: 对于不想了解 Nix 语言的用户，可以当成 JSON 文件来书写和阅读配置
- 对 Nix 用户友好: 对于已经了解 Nix 语言的用户，可以以接近 Nix 的体验来书写和阅读配置
- 对类型驱动开发友好: 对于习惯依赖静态类型进行编程的用户，可以以接近 Haskell/TypeScript 的体验来书写和阅读配置

设计思路
------

### 兼容 JSON 和 部分 Nix 语法

- 以 JSON 作为 求值过程的 Normal Form
- 支持部分 Nix 常用语法

### 渐进静态类型

- 提供类型标注能力，并且这些类型标注可以被运行时访问 (类似 Python)
- 通过 partial evaluation 静态化大量运行期开销 (类似 Julia)
- 通过独立于执行的 类型推断引擎（abstract interpreter）为 Language Server 提供 AOT 的类型推断能力
